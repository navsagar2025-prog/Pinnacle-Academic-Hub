Domain: paconline.in
Support Email: care@paconline.in

Project Objective
Build a production-ready, scalable, secure, and mobile-first web platform for Pinnacle Academic Classes on the domain paconline.in. The platform must serve as the institute’s primary digital presence for admissions, course discovery, lead generation, student/parent/teacher/admin portals, online learning access, fee management, notices, results, and content publishing.

The website must be designed and developed in a way that supports a future Android app without requiring a major rewrite of business logic, data contracts, or design system. The web platform should act as the foundation for a later mobile app ecosystem.

Product Vision
Create a premium EdTech/coaching institute platform that combines:
- Public-facing trust-building website
- Secure student and parent self-service portal
- Teacher operations portal
- Admin control panel
- Scalable backend APIs
- Mobile-ready architecture for future Android app integration

Business Goals
- Increase admissions enquiries and conversions
- Digitize student, parent, teacher, and admin workflows
- Provide structured access to classes, materials, tests, results, and fees
- Build a professional, premium, high-trust brand presence
- Create a reusable backend and design system that can power a future Android app

Primary Users
- Prospective students
- Parents
- Existing students
- Teachers/faculty
- Admin staff / institute management
- Counselors / admissions team (optional future role)

Platform Requirements
This is a real production platform, not a demo.
The build must include:
- Real authentication
- Real backend APIs
- Database persistence
- Role-based access control
- File/media handling
- Form submission and CRM capture
- Fee/payment workflow integration readiness
- Secure production deployment
- Admin-controlled content management
- Auditability and maintainability

Future Android App Readiness
Design the platform so that Android app development can reuse:
- The same backend APIs
- The same authentication system
- The same roles and permissions
- The same data models
- The same business rules
- The same design tokens and component logic where applicable

Do not tightly couple critical flows to web-only assumptions.
All core business functionality must be API-first.

Recommended Architecture
Frontend:
- Next.js latest stable version with TypeScript
- App Router
- Server components where useful, client components where necessary
- Tailwind CSS
- shadcn/ui
- React Hook Form + Zod
- TanStack Query for client-side data fetching/caching where appropriate

Backend:
Choose one robust production-ready backend approach:
Option A:
- Next.js API routes / server actions for simple integrated deployment
Option B:
- Separate backend using Node.js + NestJS or Express + TypeScript
Preferred if long-term app scale is expected

ORM:
- Prisma preferred

Storage:

Payments:

Notifications:

Infra / Deployment:

- Logging, monitoring, backups, and error tracking ready
